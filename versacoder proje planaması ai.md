### 3.2 Temel Mimari Bileşenler ve Katman Yapısı

   - CQRS (Command Query Responsibility Segregation) ve MediatR/Pipeline Behaviors deseni.

4. **Protocol & Genişletilebilirlik Katmanı (`VersaCoder.Protocol`, `VersaCoder.Infrastructure.MCP`, `VersaCoder.Infrastructure.Plugins`):**
   - **Full Model Context Protocol (MCP):** Hem MCP Host hem MCP Client olarak çalışabilme, harici araç ve veri kaynaklarını dinamik bağlama.

Günümüz yazılım dünyasında yapay zekâ asistanları (Copilot, web tabanlı LLM sohbetleri, basit kod tamamlayıcılar) yaygınlaşmış olsa da, kurumsal ve endüstriyel yazılım geliştirme süreçlerinde **kritik mühendislik açıklarına**, **mimari bozulmalara** ve **yönetilebilirlik krizlerine** yol açmaktadır.

---

### 4.1 Mimari Erozyon ve "God Object / Spagetti Kod" Üretimi

* **Mevcut Sorun:** Geleneksel yapay zekâ araçları, projenin kurumsal mimarisini (Clean Architecture, SOLID, Onion, CQRS, Hexagonal) kavrayamaz. Ürettikleri çözümleri genellikle tek bir dosyaya, Controller veya Form sınıfının içine (God Class) yığar; katman sınırlarını ihlal eder ve kod tabanında çok kısa sürede devasa bir mimari borç (Technical Debt) yaratır.
* **Versa Coder Çözümü:** 50+ bağımsız **Class Library (DLL)** katman hiyerarşisini ve katı mimari kuralları (`Architect Agent` ve Roslyn AST analizörleri) zorunlu kılar. Kod üretimi her zaman `Domain -> Abstractions -> Application -> Infrastructure -> UI` akışına uygun gerçekleşir; katman ihlalleri derleme ve review aşamasında otomatik engellenir.

---

### 4.2 Sığ Bağlam (Context Degradation) ve Parçalanmış Proje Görüşü

* **Mevcut Sorun:** Standart AI araçları yalnızca açık olan dosyayı veya sınırlı birkaç kod satırını görür. Projenin bağımlılık ağacını, veritabanı şemasını, domain event'lerini ve servis kontratlarını bir bütün olarak algılayamadığı için sıklıkla var olan sınıfları yeniden tanımlar, hatalı DTO eşlemeleri yapar veya halüsinasyon (hallucination) üretir.
* **Versa Coder Çözümü:** **`Infrastructure.Context`** ve **`Infrastructure.ProjectAnalysis`** modülleri üzerinden tüm projeyi semantik olarak indeksler. Roslyn tabanlı AST motoru ve **Epoch Assembly** mekanizması ile projenin tip hiyerarşisini, semantik modellerini ve bağımlılık grafını tam bağlam olarak ajana iletir.

---

### 4.3 Otonom İş Ayrıştırma ve Orkestrasyon Yokluğu (Orchestration Deficit)

* **Mevcut Sorun:** Geliştiriciler, karmaşık bir modül veya özellik eklerken yapay zekâyı satır satır mikro-yönetmek (Micro-management) zorundadır. "Şimdi arayüzü yaz", "Şimdi servisi yaz", "Şimdi DTO'yu ekle", "Şimdi testini yaz" şeklinde onlarca manuel prompt girilmektedir.
* **Versa Coder Çözümü:** **Multi-Agent Swarm & Task Decomposition** motoru devreye girer. Kullanıcının tek bir yüksek seviyeli gereksinimini (Intent) analiz eder; bunu alt görevlere böler ve sırasıyla **Architect**, **Developer**, **Reviewer**, **Security** ve **Testing** ajanlarına dağıtarak uçtan uca otonom olarak yürütür.

---

### 4.4 Kapalı Ekosistemler ve Araç İzolasyonu (Tool Silos & Vendor Lock-in)

* **Mevcut Sorun:** Mevcut IDE eklentileri kapalı kutudur. Harici CLI araçlarına, şirket içi API'lara, veritabanlarına veya özel donanım derleyicilerine bağlanmak imkânsızdır ya da karmaşık entegrasyonlar gerektirir.
* **Versa Coder Çözümü:** Açık endüstri standardı olan **Model Context Protocol (MCP)** desteği ve `AssemblyLoadContext` tabanlı **Dinamik C# Plugin Sandbox** mimarisi sunar. Sistem hem MCP Client hem MCP Server olarak çalışarak projenin ihtiyaç duyduğu 100+ harici aracı, CLI'ı ve veri kaynağını güvenle orkestre eder.

---

### 4.5 Kurumsal Güvenlik, Denetlenebilirlik ve Zafiyet Açıkları

* **Mevcut Sorun:** AI tarafından üretilen kodlar genellikle güvenlik kontrollerinden geçmez; SQL Injection, XSS, CSRF, güvensiz deserialization (OWASP Top 10) gibi açıklar içerir. Ayrıca API anahtarları düz metin olarak promptlara sızabilir ve yapılan değişikliklerin geriye dönük denetim kaydı (Audit Trail) tutulamaz.
* **Versa Coder Çözümü:** **`Infrastructure.Security`** katmanı ile AES-256-GCM şifreli credential kasası sağlar. **Security & Policy Agent** her kod parçasını OWASP 2025 standartlarında tarar. Kritik işlemler (dosya silme, migration çalıştırma, API çağırma) **Human-in-the-Loop Onay Kapıları (Approval Gates)** ile kilitlenir ve tüm session adımları değiştirilemez (immutable) audit loglarına kaydedilir.

* **Versa Coder Çözümü:** **`Infrastructure.Embedded`** ve **`Infrastructure.Driver`** altyapıları ile donatılmıştır. Sektörel uzman ajanlar; donanım register haritalarını, gerçek zamanlı (real-time lock-free) kısıtlamaları, bellek sınırlamalarını ve sektörel uyumluluk kurallarını doğrudan derleme sürecine entegre eder.

# 5. Projeyi Açıkla (Detaylı Sistem Mimarisi ve Çalışma Mekanizması)

**Versa Coder**, kullanıcının doğal dilde belirttiği yüksek seviyeli yazılım hedeflerini alan, bu hedefleri çok adımlı deterministik mühendislik süreçlerine dönüştüren, uzman ajan sürülerini (Agent Swarm) koordine eden ve sonucu endüstriyel kalite standartlarında üreten **otonom bir yazılım geliştirme ekosistemidir**.

Bu bölümde sistemin iç işleyişi, katmanlar arası veri akışı, sihirbaz (Wizard) mimarisi, MCP entegrasyonu, hibrit bellek motoru ve kullanıcı arayüzü derinlemesine açıklanmaktadır.

---

### 5.1 Uçtan Uca Mühendislik Yaşam Döngüsü (End-to-End Execution Lifecycle)

Versa Coder içerisinde bir geliştirme veya refactoring talebi şu 6 ana aşamadan geçerek icra edilir:

```
┌─────────────────┐     ┌──────────────────────┐     ┌──────────────────────┐
│ 1. INTENT & AST │ ──> │ 2. SESSION WIZARD    │ ──> │ 3. SWARM ALLOCATION  │
│    ANALYSIS     │     │    (Config Synthesis)│     │    (DAG Workflow)    │
└─────────────────┘     └──────────────────────┘     └──────────────────────┘
         │                                                       │
         ▼                                                       ▼
┌─────────────────┐     ┌──────────────────────┐     ┌──────────────────────┐
│ 6. PERSISTENCE  │ <── │ 5. VERIFICATION &    │ <── │ 4. EXECUTION, TOOLS  │
│    & AUDIT SYNC │     │    SELF-HEALING      │     │    & MCP INVOCATION  │
└─────────────────┘     └──────────────────────┘     └──────────────────────┘
```

1. **Niyet ve Proje Analizi (Intent & AST Analysis):**
   Kullanıcı Chat ekranından bir talep girdiğinde (Örn: *"Mevcut veritabanı erişim katmanını Dapper'dan EF Core 8'e geçir, Repository ve UnitOfWork desenini Clean Architecture kurallarına göre refactor et ve unit testlerini yaz"*), Niyet Çözümleme Motoru (`IntentAnalysisEngine`) devreye girer. Projenin bağımlılık ağacı, hedef sınıflar ve risk seviyesi Roslyn AST üzerinden taranır.

2. **Session Agentic Agent Wizard (Yapılandırma Sentezi):**
   Sistem doğrudan kontrolsüz bir kod üretimine geçmez. Kullanıcıya özel dinamik bir **Session Wizard** açılır. Bu sihirbaz; göreve en uygun ajan kombinasyonunu, kullanılacak LLM modellerini, gerekli MCP araçlarını ve güvenlik izinlerini önceden yapılandırır. Kullanıcı "Onayla / Başlat" dediğinde **Immutable `SessionConfiguration`** nesnesi üretilir.

3. **Görev Ayrıştırma ve Sürüye Dağıtım (Swarm Task Allocation):**
   Orchestrator Agent, işi bir Yönlü Döngüsüz Graf (DAG - Directed Acyclic Graph) haline getirir:
   - **`Architect Agent`**: Yeni katman sınırlarını, interface kontratlarını ve DTO yapılarını tasarlar.
   - **`Developer Agent`**: Tasarıma uygun C# 12 / .NET 8 kodlarını üretir.
   - **`Security Agent`**: SQL injection, hassas veri sızıntısı ve OWASP zafiyet kontrollerini yapar.
   - **`Testing Agent`**: xUnit ve FluentAssertions tabanlı birim testleri oluşturur.

4. **Yürütme, Araç ve MCP Çağrıları (Execution & Tool Gateway):**
   Ajanlar, tanımlı yetkileri dahilinde **MCP Araçları**, **Roslyn AST Manipülatörleri**, **Git Servisi** ve **Dosya Sistemi** araçlarını çalıştırır. Her araç çağrısı güvenlik duvarından (Policy Engine) geçer; izinsiz hiçbir dış kaynak erişimine veya yıkıcı dosya işlemine izin verilmez.

5. **Doğrulama, Derleme ve Kendi Kendini Onarma (Verification & Self-Healing):**
   Kod yazımı bittiğinde Roslyn derleyicisi arka planda kodu derler ve testler otomatik koşulur:
   - Derleme hatası veya kırılan test varsa, `Self-Healing Loop` devreye girer.
   - Hata çıktısı doğrudan ilgili ajana geri beslenir ve ajan kodu düzeltene kadar iterasyon devam eder.
   - Kod kalitesi, SOLID ve Clean Code kuralları `Reviewer Agent` tarafından onaylanmadan süreç tamamlanmaz.

6. **Kalıcılık, Denetim ve Bilgi Kasası Senkronizasyonu (Persistence & Audit Sync):**
   İşlem başarıyla tamamlandığında tüm değişiklikler Git staging alanına alınır, detaylı bir mimari karar kaydı (ADR) oluşturulur, SQLite/SQL Server oturum geçmişine yazılır ve `.ai` bilgi kasasındaki (Knowledge Vault) kural ve hafıza dosyaları güncellenir.

### 5.2 Katmanlar Arası İletişim ve Veri Akış Mimarisi

Versa Coder, **Inversion of Control (IoC)** ve **Loose Coupling** ilkelerini katı bir şekilde uygular. Katmanlar arasındaki veri ve kontrol akışı şu hiyerarşiyle yönetilir:

```
[ VersaCoder.UI (DevExpress WinForms) ]
                │  (Commands / ViewModels / SignalR Events)
                ▼
[ VersaCoder.Host (Autofac DI Container & Config) ]
                │  (MediatR CQRS Dispatcher)
                ▼
[ VersaCoder.Application (UseCases / Pipelines / Validation) ]
        │                                       │
        ▼ (Pure Rules & Contracts)              ▼ (Tool / Provider Gateways)
[ VersaCoder.Domain & Abstractions ]     [ VersaCoder.Protocol & MCP ]
                                                │
                                                ▼ (Implementations)
                                         [ VersaCoder.Infrastructure.* (28+ DLL) ]
```

* **`VersaCoder.Domain` & `Abstractions`:** Çekirdek varlıkları (Entity, ValueObject, DomainEvent) ve tüm servis arayüzlerini (`IAgentRunner`, `IToolGateway`, `IMcpClient`, `IRepository`) barındırır; hiçbir dış kütüphaneye bağımlı değildir.
* **`VersaCoder.Application`:** CQRS mimarisi ile `CreateSessionCommand`, `ExecuteTaskCommand`, `EvaluateRuleQuery` gibi komut ve sorguları `MediatR Pipeline Behaviors` üzerinden (Validation -> Logging -> Security -> Transaction) işler.
* **`VersaCoder.Protocol` & `Infrastructure.MCP`:** JSON-RPC 2.0 üzerinden hem harici MCP sunucularına bağlanır hem de Versa Coder'ın kendi yeteneklerini dış dünyaya bir MCP Server olarak sunar.
* **`VersaCoder.CrossCutting`:** Tüm katmanlara entegre merkezi exception handling, loglama (Serilog), metrikler (OpenTelemetry) ve validation (FluentValidation) sağlar.

### 5.3 Session Agentic Agent Wizard'ın İç Çalışma Mekanizması

Session Wizard, kullanıcının sistem üzerindeki kontrolünü maksimize eden **Human-in-the-Loop** yönetim panelidir:

1. **Akıllı Profilleme:** Wizard açıldığında projenin türünü (.NET, Embedded, C++, Web, Driver) algılar ve varsayılan ajan ekibini otomatik seçer.
2. **Çoklu Oturum Tipleri:**
   - **Tekli Session (Single Agent):** Hızlı ve küçük çaplı sorgular/düzenlemeler için.
   - **Çoklu Sürü Session (Swarm Intelligence):** Mimar, Geliştirici, Reviewer ve Testçinin paralel çalıştığı büyük özellik geliştirmeleri.
   - **Zincirleme Session (Chained Pipeline):** Bir ajanın çıktısının diğerinin girdisi olduğu sıralı analiz süreçleri.
   - **Dağıtılmış Session (Distributed Agentic Node):** Ağ üzerindeki farklı MCP veya arka plan sunucularına dağıtılmış görevler.
3. **Dinamik System Prompt Sentezleyici:** Wizard üzerindeki tüm seçimler (sektör kuralları, dil standartları, güvenlik seviyesi, bellek derinliği) birleştirilerek her ajan için dinamik, çelişkisiz ve amaca özel bir **Meta-System-Prompt** sentezlenir.

### 5.4 Model Context Protocol (MCP) ve Plugin Sandbox Mimarisi

Versa Coder, genişletilebilirliğini iki temel taşıyıcı üzerine kurar:

* **Model Context Protocol (MCP) Gateway:**
  - `stdio` ve `SSE (Server-Sent Events)` taşıma protokolleri üzerinden çalışan MCP istemcileri.
  - Veritabanı sorgulayıcıları, API test araçları, dokümantasyon arama servisleri ve harici LLM context sağlayıcıları dinamik olarak sisteme bağlanabilir.
* **İzole Plugin Sandbox (`AssemblyLoadContext`):**
  - Üçüncü parti C# DLL plugin'leri ana uygulama belleğini kirletmeden ayrı bir `AssemblyLoadContext` içinde yüklenir ve çalıştırılır.
  - Eklenti çökerse veya bellek tüketim sınırını aşarsa ana IDE etkilenmez, eklenti güvenle izole edilip bellekten düşürülür (Unload).

### 5.5 Çift Katmanlı Hibrit Bellek ve Sürekli Öğrenme

Versa Coder, unutkan yapay zekâ (Amnesic AI) problemini çift katmanlı bellek mimarisi ile ortadan kaldırır:

1. **Kısa Dönemli Çalışma Belleği (Working Memory / Epoch Assembly):**
   - Aktif oturumdaki mesaj geçmişi, çağrılan araçların çıktıları ve token bütçesini aşmayacak şekilde dinamik kayan pencere (Sliding Window) yöntemiyle yönetilir.
2. **Uzun Dönemli Kurumsal Bellek (Knowledge Vault & Vector Store):**
   - **`.ai` Bilgi Kasası:** Markdown / Obsidian tabanlı SSOT (Single Source of Truth) dosyaları (`rules/`, `skills/`, `decisions/`, `memory/`).
   - **Vektörel & Semantik Arama:** Proje dokümantasyonu ve geçmiş oturumlarda çözülen hatalar semantik embedding vektörleri ile SQLite tabanında indekslenir.
3. **Geri Bildirimle Öğrenme Döngüsü (Continuous Learning Loop):**
   - Geliştirici bir kod bloğunu elle düzelttiğinde veya bir kural eklediğinde, sistem aradaki farkı (Diff) analiz eder, öğrenilen kuralı `.ai/learning/` dizinine kaydeder ve gelecekteki oturumlarda aynı hatayı tekrarlamaz.

Kullanıcı deneyimi, kurumsal masaüstü gücünü ve modern reaktif arayüz dinamizmini birleştirir:

* **Çoklu Panel Docking:** DevExpress DockManager ve DocumentManager ile kod editörü, ajan konsolu, test paneli ve proje gezgini esnek bir şekilde düzenlenebilir.
* **Görsel Yürütme Grafiği (Visual Execution Graph):** Hangi ajanın o anda hangi görevi yürüttüğü, hangi araçları çağırdığı ve iş akışının ilerleme yüzdesi gerçek zamanlı nod/grafik tabanlı ekranda izlenir.

* **Onay Kapıları (Approval Gate UI):** Ajanın yapacağı kritik dosya yazma, Git commit veya terminal çalıştırma işlemleri kullanıcıya net diff blokları ve onay diyalogları ile gösterilir.

# Session Agentic Agent Wizard İstemi

Şimdi bir de **Chat Agent** ekranında, benim istediğim şeyi anlatarak veya prompt ile yazarak belirteceğim bir yapı istiyorum.

**“Gönder”** dediğimde bir **Session Agentic Agent Wizard** açılması gerekiyor. Bu wizard içerisinde session’ı istediğimiz gibi kurup yönetebilmeli, istediğimiz agent’ları ve özellikleri seçerek işlemi yapılandırabilmeliyiz.

Wizard içerisinde **Chat Session** ve **Agent Session** ayarlarını yapabilmeli, session’ın nasıl çalışacağını belirleyebilmeli, istediğimiz agent’ları ve gerekli özellikleri seçerek yapılandırabilmeliyiz. Ardından ileri seviye ayarları yapıp **“Bitti”** butonuna basabilmeliyiz.

### 2. Session Agentic Agent Wizard Adım Adım Yapılandırma Mimarisi

Wizard, kullanıcıya karmaşık ayarları basitleştiren ve her aşamayı tam kontrolde tutan **DevExpress Wizard Control / Tabbed View** tabanlı 6 adımlı bir konfigürasyon akışı sunar:

#### Adım 1: Chat Session Yapılandırması (Oturum Tipi ve Bağlam Ayarları)
* **Oturum Tipi Seçimi:**
  - *Single Agent Session:* Hızlı analiz ve tekil dosya düzenlemeleri.
  - *Multi-Agent Swarm Session:* Paralel çalışan mimar, kodlayıcı, testçi ve denetleyici ajanlar.
  - *Chained Pipeline Session:* Sıralı onay ve aşamalı geçiş gerektiren refactoring akışları.
  - *Distributed Node Session:* Farklı sunuculardaki MCP veya arka plan servislerine dağıtılmış görevler.
* **Bağlam Bellek Stratejisi (Epoch Memory):** Oturuma projenin hangi kısımlarının (Tüm AST, sadece ilgili DLL'ler, veritabanı şeması, `.ai` kural dosyaları) dahil edileceğinin seçimi.
* **Otonomluk ve Onay Seviyesi:** Tam Otonom (Full Auto), Yarı Otonom (Human-in-the-Loop Approval Gates) veya Yalnızca İnceleme (Review Only).

#### Adım 2: Agent Session Yapılandırması (Rol ve Model Eşleştirme)
* **Ajan Takımı Seçimi:** Görevde yer alacak uzman rollerin (Architect, Developer, Reviewer, Security, Testing, Sektörel Uzman) aktif/pasif edilmesi.
* **Model Sağlayıcı Eşleştirmesi:** Her ajan için en uygun LLM modelinin seçilmesi (Örn: Mimar için *Claude 3.5 Sonnet / Reasoning Modeli*, Hızlı kodlama için *GPT-4o / DeepSeek-Coder*, Güvenlik için *Yerel LLM*).
* **Hiperparametre Ayarları:** Sıcaklık (Temperature), Top-P, Maksimum Token ve Düşünme Bütçesi (Thinking Budget) değerlerinin role özel kalibrasyonu.

#### Adım 3: Araç (Tool) ve MCP İzin Matrisi (Capability & Security Gates)
* **MCP Servis İzinleri:** Hangi ajanların hangi MCP sunucularına (Dosya sistemi, Roslyn AST, SQL Server, Git CLI, Web Search) erişebileceğinin belirlenmesi.
* **Yıkıcı İşlem Koruması:** Dosya silme, veritabanı şeması değiştirme veya terminal komutu çalıştırma işlemlerinde zorunlu kullanıcı onay kutularının atanması.

#### Adım 4: Sektörel Standartlar ve Mimari Kural Enjeksiyonu
* Projeye özel regülasyonların seçimi (Otomotiv için *MISRA/AUTOSAR*, Sağlık için *HL7/FHIR*, Web/API için *OWASP Top 10:2025*, Finans için *ISO 20022*).

## 4. Akıllı Yönlendirme ve Ücretsiz Model Fallback Stratejisi (Smart Router)

Versa Coder, oturum başlatılırken maliyet optimizasyonunu önceliklendiren bir **Smart Model Router** içerir:

```
┌──────────────────────────────────────────────────────────────────────────────────┐
│                             GÖREV / PROMPT GİRİŞİ                                │
└──────────────────────────────────────────────────────────────────────────────────┘
                                        │
                                        ▼
┌──────────────────────────────────────────────────────────────────────────────────┐
│                         VERSACODER SMART MODEL ROUTER                            │
│  1. Kullanıcı tercihi Ücretsiz Modeller (Free-Tier) mi?                          │
│     ├── EVET ──> OpenCode Zen Free Models (DeepSeek V4 Flash / Nemotron 3.5)     │
│     │            │ (Eğer Rate-Limit / 429 veya Hata Alınırsa)                   │
│     │            ▼                                                               │
│     │           Fallback: OpenRouter Free / Ollama Yerel Model                   │
│     └── HAYIR ──> Paid Enterprise Model (Claude Sonnet 3.5 / GPT-4o)             │
└──────────────────────────────────────────────────────────────────────────────────┘
```

1. **Öncelikli Yönlendirme:** Küçük ve orta ölçekli görevlerde (kod tamamlama, dokümantasyon, linter analizleri, birim test üretimi) otomatik olarak `OpenCode Free Modelleri` tercih edilir.
2. **Kademeli Fallback:** Eğer bir OpenCode Free modeli yoğunluktan dolayı `HTTP 429 Too Many Requests` veya zaman aşımı verirse, sistem kullanıcıyı bekletmeden sıradaki ücretsiz modele (`DeepSeek V4 Free -> Nemotron 3.5 Free -> OpenRouter Free -> Ollama Local`) otomatik geçiş yapar.
3. **Sıfır Maliyetli Geliştirme:** Kullanıcı hiçbir API anahtarı veya bakiye girmese dahi, Versa Coder kutudan çıktığı anda OpenCode free modelleri ve yerel motorlarla tam teşekküllü bir IDE asistanı olarak çalışabilir.

### 5.1 OpenCode Free HTTP İstemcisi (`OpenCodeFreeHttpClient.cs`)

```csharp
using System.Net.Http.Headers;
using System.Net.Http.Json;
using System.Runtime.CompilerServices;
using System.Text;
using System.Text.Json;
using System.Text.Json.Serialization;
using VersaCoder.Domain.AI.Contracts;
using VersaCoder.Domain.AI.Models;

namespace VersaCoder.Infrastructure.AI.Providers.OpenCode;

public sealed class OpenCodeFreeHttpClient : IOpenCodeFreeClient
{
    private readonly HttpClient _httpClient;
    private const string DefaultEndpoint = "https://opencode.ai/zen/v1/chat/completions";
    private const string ModelsApiUrl = "https://models.opencode.ai/api.json";

    public OpenCodeFreeHttpClient(HttpClient httpClient)
    {
        _httpClient = httpClient ?? throw new ArgumentNullException(nameof(httpClient));
        ConfigureDefaultHeaders();
    }

    private void ConfigureDefaultHeaders()
    {
        _httpClient.DefaultRequestHeaders.Clear();
        // OpenCode kaynak kodundaki standart başlıklar (Bypass / Free Gateway Header İmzaları)
        _httpClient.DefaultRequestHeaders.Add("HTTP-Referer", "https://opencode.ai/");
        _httpClient.DefaultRequestHeaders.Add("X-Title", "opencode");
        _httpClient.DefaultRequestHeaders.Add("X-Source", "opencode");
        _httpClient.DefaultRequestHeaders.Add("X-BILLING-INVOKE-ORIGIN", "OpenCode");
        _httpClient.DefaultRequestHeaders.UserAgent.ParseAdd("opencode/1.0.0/client");
    }

    public async Task<string> SendChatCompletionAsync(
        string modelId,
        IEnumerable<ChatMessageDto> messages,
        CancellationToken cancellationToken = default)
    {
        var requestPayload = new
        {
            model = modelId,
            messages = messages.Select(m => new { role = m.Role, content = m.Content }),
            stream = false,
            temperature = 0.2
        };

        using var request = new HttpRequestMessage(HttpMethod.Post, DefaultEndpoint)
        {
            Content = JsonContent.Create(requestPayload)
        };

        using var response = await _httpClient.SendAsync(request, cancellationToken).ConfigureAwait(false);
        response.EnsureSuccessStatusCode();

        var jsonResponse = await response.Content.ReadAsStringAsync(cancellationToken).ConfigureAwait(false);
        using var doc = JsonDocument.Parse(jsonResponse);
        return doc.RootElement
            .GetProperty("choices")[0]
            .GetProperty("message")
            .GetProperty("content")
            .GetString() ?? string.Empty;
    }

    public async IAsyncEnumerable<string> StreamChatCompletionAsync(
        string modelId,
        IEnumerable<ChatMessageDto> messages,
        [EnumeratorCancellation] CancellationToken cancellationToken = default)
    {
        var requestPayload = new
        {
            model = modelId,
            messages = messages.Select(m => new { role = m.Role, content = m.Content }),
            stream = true,
            temperature = 0.2
        };

        using var request = new HttpRequestMessage(HttpMethod.Post, DefaultEndpoint)
        {
            Content = JsonContent.Create(requestPayload)
        };

        using var response = await _httpClient.SendAsync(
            request, 
            HttpCompletionOption.ResponseHeadersRead, 
            cancellationToken
        ).ConfigureAwait(false);

        response.EnsureSuccessStatusCode();

        using var stream = await response.Content.ReadAsStreamAsync(cancellationToken).ConfigureAwait(false);
        using var reader = new StreamReader(stream, Encoding.UTF8);

        while (!reader.EndOfStream && !cancellationToken.IsCancellationRequested)
        {
            var line = await reader.ReadLineAsync(cancellationToken).ConfigureAwait(false);
            if (string.IsNullOrWhiteSpace(line)) continue;
            if (line.StartsWith("data: [DONE]")) break;
            if (!line.StartsWith("data: ")) continue;

            var jsonChunk = line["data: ".Length..];
            using var doc = JsonDocument.Parse(jsonChunk);
            var choices = doc.RootElement.GetProperty("choices");
            if (choices.GetArrayLength() > 0)
            {
                var delta = choices[0].GetProperty("delta");
                if (delta.TryGetProperty("content", out var contentElement))
                {
                    var text = contentElement.GetString();
                    if (!string.IsNullOrEmpty(text))
                    {
                        yield return text;
                    }
                }
            }
        }
    }
}
```

### 5.2 Dinamik Model Kataloğu Senkronizasyon Servisi (`ModelsDevCatalogSyncService.cs`)

```csharp
using System.Text.Json;
using Microsoft.Extensions.Logging;

namespace VersaCoder.Infrastructure.AI.Catalog;

public sealed class ModelsDevCatalogSyncService
{
    private readonly HttpClient _httpClient;
    private readonly ILogger<ModelsDevCatalogSyncService> _logger;
    private const string ModelsApiUrl = "https://models.opencode.ai/api.json";

    public ModelsDevCatalogSyncService(HttpClient httpClient, ILogger<ModelsDevCatalogSyncService> logger)
    {
        _httpClient = httpClient;
        _logger = logger;
    }

    public async Task<IReadOnlyList<string>> FetchLiveFreeModelsAsync(CancellationToken cancellationToken = default)
    {
        try
        {
            using var request = new HttpRequestMessage(HttpMethod.Get, ModelsApiUrl);
            request.Headers.UserAgent.ParseAdd("opencode/1.0.0/client");

            using var response = await _httpClient.SendAsync(request, cancellationToken).ConfigureAwait(false);
            response.EnsureSuccessStatusCode();

            var json = await response.Content.ReadAsStringAsync(cancellationToken).ConfigureAwait(false);
            using var doc = JsonDocument.Parse(json);

            var freeList = new List<string>();
            foreach (var providerProp in doc.RootElement.EnumerateObject())
            {
                if (providerProp.Value.TryGetProperty("models", out var modelsElement))
                {
                    foreach (var modelProp in modelsElement.EnumerateObject())
                    {
                        var modelObj = modelProp.Value;
                        if (modelObj.TryGetProperty("cost", out var costElement))
                        {
                            var inputCost = costElement.GetProperty("input").GetDecimal();
                            var outputCost = costElement.GetProperty("output").GetDecimal();

                            if (inputCost == 0 && outputCost == 0)
                            {
                                freeList.Add($"{providerProp.Name}/{modelProp.Name}");
                            }
                        }
                    }
                }
            }

            _logger.LogInformation("Toplam {Count} adet ücretsiz model canlı katalogdan senkronize edildi.", freeList.Count);
            return freeList;
        }
        catch (Exception ex)
        {
            _logger.LogWarning(ex, "Canlı model kataloğu çekilemedi, yerel statik katalog kullanılacak.");
            return OpenCodeFreeModelCatalog.FreeModels.Select(m => m.ModelId).ToList();
        }
    }
}
```
